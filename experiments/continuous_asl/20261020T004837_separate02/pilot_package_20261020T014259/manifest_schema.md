# Pilot envelope and feature artifacts v1

`manifest.schema.json` describes the structural envelope; `validate_pilot.py` is the stricter semantic validator. Templates contain no participant facts. Synthetic examples under a dry-run directory are a complete format demonstration with `SYN_` identifiers and fake tokens, not consent or ASL ground truth. Unknown/missing information must remain pending/unscored; do not manufacture fields to pass.

Top-level schema: `apphear.streaming_pilot.manifest.v1`; mode `REAL` or explicitly `SYNTHETIC`; purpose `EVALUATION_ONLY`; `training_allowed:false`. Participants are ordered PILOT_1_EVAL then PILOT_2_EVAL. `permission_review`, per-signer consent/qualification and signer-history coverage must all be human verified for real mode. An identity_key is a stable private registry key assigned by a human identity audit, not a new random alias. Registry entries preserve historical signer/role identity so cross-role/person overlap is rejected. Mandatory coverage: current word training, current segmentation training, legacy isolated frozen partitions, and prior phone design. Unresolvable identity/exposure is a real readiness blocker.

Consent requires human reference/reviewer, permitted actions RECORD/LOCAL_PROCESS/ANNOTATE/EVALUATE, established UTC time, future retention-until UTC time, and withdrawn:false. Empty/PENDING approvals reject before any artifact path resolution, hash, media read or feature access. Syntax cannot establish the authenticity of these human attestations. Real data root must be outside the repository; artifact paths are relative, remain inside that root and cannot traverse links/junctions. Reports are new files only.

Each recording links recording_id, session_id, signer_id and prompt_id to immutable hashed artifacts: media; capture_index; raw_observations; segmentation_features; annotations; and recognition_windows. It also requires finite source start/end times, SOURCE_MONOTONIC_MS, UPRIGHT_UNMIRRORED_SOURCE_RGB, device pseudonym, nominalFPS and a producer/config/model reference. Record optional conditions, retake lineage and clock-calibration evidence alongside these required fields. Paths are slash-separated relative strings. SHA-256 is64 lowercase hexadecimal characters. Repeated raw-media hashes are rejected rather than counted twice.

`capture_index` JSON: schema `apphear.streaming_pilot.capture_index.v1`, recording_id and frames list `{frame_index,source_timestamp_ms}`. Frame IDs must be contiguous0..N-1, source times finite/strictly increasing and inside recording bounds. These are original decoded source timestamps, not nominal-FPS reconstruction. A genuine raw-observation subset may skip source frames; every retained frame/time pair must exactly join the source index. This validator does not decode video or authenticate a fabricated frame index: a human-reviewed producer/decode provenance reference remains required for real acceptance.

`raw_observations` NPZ uses the existing `save_raw_sequence`/`load_raw_sequence` format. `metadata_json` declares `apphear.perception_vnext.raw.v1`, recording_id, signer_id and synthetic true/false. Existing geometry/visibility arrays are preserved, with finite strictly increasing float64 timestamp_ms and genuine integer frame_index. Schema is checked before vector access. Invalid joints may remain NaN only where the existing raw contract's validity flags permit it. No new landmark layout is introduced.

`segmentation_features` NPZ keys are exactly schema_version=`apphear.perception_vnext.segmentation_features.v1`, X float32[N,378], timestamp_ms float64[N] and frame_index[N]. Every row joins the raw observations exactly. Stored X must match `derive_causal_segmentation_features(raw)` at absolute tolerance1e-6/relative0. The tolerance compares a pinned existing recipe; it does not change inputs or waive schema mismatches.

`annotations` JSON: schema `apphear.streaming_pilot.annotations.v1`, recording_id, signer_id, provenance and intervals. Provenance kind is QUALIFIED_ASL_REVIEW for real data; requires two distinct qualified-reviewer references, prediction_blinded:true, adjudication:COMPLETE and a retained review reference. Intervals are ordered, non-overlapping source-time `[start_ms,end_ms)` rows with unique interval_id and type SIGN, NO_SIGN, OOV_SIGN or UNCERTAIN. SIGN requires an authentic gloss and sequence_id. NO_SIGN requires null gloss/sequence_id and one of NO_VISIBLE_HANDS, VISIBLE_IDLE, FACE_ADJACENT, ACCIDENTAL_MOTION. OOV and uncertain content cannot be joined as a verified sequence. OOV is not no-sign exposure. Human references must establish actual review; software cannot judge linguistic truth.

`sequences` contains sequence_id, start/end source times, label_type AUTHENTIC_ASL_GLOSS_SEQUENCE, ordered glosses and interval_ids. Each referenced SIGN interval must lie inside its sequence, name that sequence and match its token order exactly. Every SIGN joins exactly once. Sequence IDs/interval IDs are globally unique in the intake; bounds cannot overlap or exceed recordings. A multi-sign sequence is a transcript/evaluation unit, **not one recognition-v2 input**. English topic prompts/translations never fill these targets. If labels are unavailable, retain UNCERTAIN/OOV intervals, obtain review, and do not claim a gloss sequence or a passed positive-data gate.

`recognition_windows` links each SIGN interval once to its own features, interval_id, exact reference start/end and basis REFERENCE_DIAGNOSTIC_ONLY. The validator slices genuine raw observations inside that single-sign interval and reuses `temporal_view_v2(condition='dense')`, including its documented selection to at most96 genuine observations. NPZ keys: schema_version=`apphear.perception_vnext.recognition.v2`, X float32[96,350], frame_mask bool[96], timestamp_ms float64[L], frame_index[L]. L equals the true mask count; source selection/time/index, padding and all features must match the existing recipe. No 258-to350 adapter exists here. Reference windows are oracle diagnostics, not automatically detected events; automatic frozen runtime windows/event logs and Android parity require separate evidence before end-to-end scoring.

Pin SHA-256 of the three existing raw/recognition/segmentation Python contract files in contract_hashes. Pin actual producer model/config identities through producer_reference; software validates recipe compatibility but does not prove RGB-to-observation provenance or live serving parity. NPZ expanded size≤128MiB, recording artifact size≤512MiB, source-frame count≤10,000, JSON≤8MiB; split long recordings into real chunks rather than truncating or silently reducing the corpus. Missing/double timestamps, missing joins, malformed bounds, wrong schemas, numerical skew, expired/withdrawn permissions and signer aliases reject the intake. No sorting, interpolation, coordinate repair, automatic label inference or file overwrite occurs.
